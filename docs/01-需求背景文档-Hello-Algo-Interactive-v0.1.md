> 项目应复用《Hello 算法》的教材结构、解释内容和多语言代码，但交互动画需要独立的 React + TypeScript 运行时。产品不追求一个万能画布，而是以统一语义事件连接多类 Renderer，并允许复杂算法组合多个场景。

# 1. 项目概述

## 1.1 一句话定义

建设一个兼具教材深度、视觉品质和可交互性的算法学习平台：用户阅读《Hello 算法》的解释内容时，可以同步查看平滑、可暂停、可回退、可变速的算法动画，以及对应代码、变量和辅助数据结构。

## 1.2 项目来源

《Hello 算法》已经提供系统化章节、静态分步图解和多语言代码，是非常成熟的内容基础。[R1] 当前需求不是重新编写一本算法教材，而是在其内容资产之上补齐高质量交互演示能力。

alg0.dev 仅作为功能形态参考：它展示了算法动画、代码高亮、变量跟踪和播放控制可以如何组合，但项目不会以其代码架构或视觉实现为主要约束。[R2]

## 1.3 为什么值得建设

- 教材已有内容规模和知识结构，避免从零建设算法目录与解释体系。

- 交互动画能够补足静态图片难以表达的连续运动、因果顺序、回溯与多结构协同。

- React + TypeScript、shadcn/ui、Motion、React Flow 等开源生态已覆盖大量通用 UI、动画和图结构能力，项目可以把主要精力集中在算法语义和教学表达上。

- 高质量设计与统一动画语言可以形成区别于传统“柱状图变色”算法网站的产品辨识度。

# 2. 现状与机会

## 2.1 《Hello 算法》的现有优势

- 完整的章节体系：数据结构、搜索、排序、图、回溯、动态规划、贪心等均有系统说明。

- 内容表达友好：使用图解、步骤说明、复杂度分析和算法特性建立完整学习链路。

- 多语言代码资产丰富，适合服务不同技术背景的学习者。

- 静态站点和开源协作流程成熟，内容更新与社区贡献基础较好。

## 2.2 当前体验缺口

| **缺口**             | **当前表现**                                               | **对学习的影响**                                         |
|----------------------|------------------------------------------------------------|----------------------------------------------------------|
| 连续过程难表达       | 主要依赖多张静态步骤图或 GIF。                             | 用户看到若干结果，但难以理解对象如何移动、为何发生变化。 |
| 代码与图解弱同步     | 代码块、图片和解释位于不同区域，缺少统一执行进度。         | 学习者需要自行建立代码行与结构变化之间的对应关系。       |
| 缺少主动探索         | 输入数据、速度、步进和回退能力有限。                       | 难以验证边界情况，也难以在关键动作中停下来观察。         |
| 不同算法表达方式割裂 | 数组、图、树、矩阵和回溯通常由不同静态素材独立制作。       | 难以形成统一的交互语言，也增加内容制作成本。             |
| 视觉表现上限受限     | 静态图清晰，但无法提供现代交互产品的空间连续性和动态反馈。 | 产品吸引力和沉浸感不足。                                 |

## 2.3 市面方案常见问题

- 把每一步当成一张完整快照，切换时重建 DOM 或 SVG，导致对象身份丢失、交换动作生硬。

- 所有算法共享同一个“数组高亮模型”，遇到树旋转、图松弛、DP 依赖、回溯撤销时表达能力不足。

- 播放器只按固定间隔翻页，无法在动画中间暂停、拖动、变速或确定性回放。

- 视觉层与算法状态耦合，快速步进或取消动画时容易出现状态错乱。

- 重功能、轻设计，组件样式和运动语言不统一。

# 3. 问题定义

| **编号** | **核心问题**                               | **需要解决的本质**                                                            |
|----------|--------------------------------------------|-------------------------------------------------------------------------------|
| P-01     | 学习者难以从静态步骤中建立连续的因果模型。 | 保留实体身份，展示比较、移动、写入、访问、撤销等真实过程。                    |
| P-02     | 动画、代码、变量和解释不同步。             | 用统一事务和时间轴驱动多个场景。                                              |
| P-03     | 不同类型算法无法被同一种图形自然表达。     | 提供 Sequence、Linked、Graph/Tree、Grid/Board、Composite 和 Custom Renderer。 |
| P-04     | 通用动画往往机械、生硬或过度花哨。         | 建立教学导向的视觉语义与 Motion Tokens。                                      |
| P-05     | 逐算法手写 UI 和动画成本过高。             | 复用 shadcn/ui 与成熟开源库，仅维护算法事件、Renderer 和少量专用场景。        |
| P-06     | 回退、拖动和变速容易破坏状态。             | 算法状态通过事件重放恢复，动画只负责表现。                                    |

| **编号** | **目标**         | **结果定义**                                                                   |
|----------|------------------|--------------------------------------------------------------------------------|
| G-01     | 高质量交互演示   | 动画平滑、对象连续、动作含义明确，支持播放、暂停、步进、回退、变速与拖动。     |
| G-02     | 覆盖不同算法形态 | 通过多 Renderer 和复合场景覆盖序列、链式结构、树、图、矩阵、棋盘、递归与回溯。 |
| G-03     | 内容与交互融合   | 复用《Hello 算法》的章节、解释和代码映射，不形成两套相互独立的内容系统。       |

| G-05     | 低成本扩展       | 新增普通算法主要编写 trace/event 生成器和场景配置，而不是重写播放器和页面。    |

# 5. 非目标

- MVP 不建设完整在线判题系统、课程系统或用户社区。

- MVP 不支持用户输入任意代码并自动生成可靠动画。

- MVP 不在浏览器中真实执行所有语言实现来驱动动画；动画由规范化算法 trace 驱动。

- MVP 不一次性覆盖《Hello 算法》的全部章节和全部算法。

- 不以 3D、粒子效果或大量弹簧动画作为主要卖点。

- 不强制所有算法套入通用 Renderer；复杂算法可以使用 Custom Renderer。

|------------------|------------------------------------|--------------------------------------------------------|

# 7. 产品范围

## 7.1 核心产品边界

```text
算法目录 / 搜索

↓

算法详情页

├─ 教材解释

├─ 主动画场景

├─ 辅助场景（队列、栈、表格、递归栈等）

├─ 代码与变量

└─ 播放器与输入控制
```

## 7.2 必须覆盖的视觉类型

| **Renderer** | **适用对象**                               | **关键动作**                                   |
|--------------|--------------------------------------------|------------------------------------------------|
| Sequence     | 数组、字符串、排序、二分、双指针、滑动窗口 | 比较、换位、指针移动、区间收缩、插入与删除     |
| Linked       | 链表、栈、队列、哈希桶、LRU                | 连接、断开、push/pop、节点进入退出、移动到头部 |
| Graph / Tree | BFS、DFS、最短路、BST、AVL、堆、Trie       | 访问节点/边、路径、松弛、插入、旋转、子树移动  |
| Grid / Board | DP、背包、编辑距离、迷宫、数独、N 皇后     | 读取依赖、写单元格、扩散、冲突、放置与撤销     |
| Composite    | Dijkstra、堆排序、回溯、复杂动态规划       | 多个场景在一个事务中同步更新                   |
| Custom       | 哈夫曼、网络流、压缩流水线、计算几何等     | 保留专用表达能力，复用通用播放器和设计系统     |

# 8. 设计与工程原则

- **内容与运行时分离：**教材文本和多语言代码属于内容层；事件、时间轴和 Renderer 属于交互运行时。

- **统一语义，不统一图形：**不同 Renderer 可以不同，但 compare、swap、visit、write、push、pop、backtrack 等语义保持一致。

- **稳定实体身份：**数组重复值、图节点、棋子和队列项都必须拥有稳定 ID，不能用值或下标代替身份。

- **算法状态独立于动画：**动画完成回调不得作为算法状态提交来源；取消动画不应破坏逻辑结果。

- **复合场景共用时间轴：**一个算法动作涉及多个区域时，由同一个 Transaction 组织节奏。

- **确定性与可回放：**输入、seed、事件版本固定后，任何步骤都可通过 checkpoint + replay 恢复。

- **美观服务于理解：**强调空间连续性、层次、聚焦和反馈，不使用无意义的弹跳与持续闪烁。

- **渐进式扩展：**先覆盖代表性算法，验证 Renderer 能力，再扩大算法目录。

# 9. MVP 技术验证算法

MVP 不以算法数量为第一目标，而以“是否覆盖主要视觉模型”为验收重点。建议使用以下六个基准算法：

| **算法** | **验证的 Renderer/能力**      | **选择原因**                                   |
|----------|-------------------------------|------------------------------------------------|
| 冒泡排序 | Sequence；稳定 ID；比较与换位 | 最适合检验重复值、对象连续性、步进和反向恢复。 |
| 二分查找 | Sequence；指针与区间          | 验证没有实体换位时的范围、指针和变量同步。     |
| BFS      | Graph + Queue                 | 验证节点、边、队列和代码在同一事务内同步。     |
| 堆排序   | Sequence + Tree               | 验证同一实体在数组和树两个场景中的映射。       |
| 0-1 背包 | Items + Grid                  | 验证 DP 依赖、单元格写入和辅助输入信息。       |
| N 皇后   | Board + Call Stack            | 验证尝试、冲突、撤销和回溯的可视化。           |

# 10. 成功标准

## 10.1 产品体验标准

- 用户在算法页无需阅读使用说明即可完成播放、暂停、下一步、上一步和速度调整。

- 关键对象在移动、交换、插入或删除前后保持可识别的视觉身份。

- 代码、变量、描述和主/辅场景不会出现明显不同步。

- 桌面端和移动端均可完成核心学习流程，而不是简单缩小桌面布局。

- 浅色与深色主题下语义状态清晰，不依赖单一颜色传达信息。

## 10.2 工程验收标准

- 同一输入和 seed 生成完全相同的事件序列。

- 任意 Marker 前进、回退、重放后算法状态一致。

- 快速切换算法、拖动时间轴或 Resize 时可取消当前动画，无状态残留。

- 基准规模下保持流畅交互；高频动画值不通过 React 全局状态逐帧更新。

- 新增普通算法无需修改播放器核心。

# 11. 关键风险与依赖

| **风险**               | **影响**                                                                             | **应对**                                                                     |
|------------------------|--------------------------------------------------------------------------------------|------------------------------------------------------------------------------|
| 《Hello 算法》授权边界 | 其文本、代码和媒体资产声明为 CC BY-NC-SA 4.0，可能影响商业使用与衍生内容授权。[R1] | 立项早期确认使用目的和授权方案；交互引擎代码与内容资产分目录、分许可证管理。 |
| 追求“万能 Renderer”    | 事件协议和 DSL 过度复杂，拖慢首版。                                                  | 通用 Renderer 覆盖常见情况，同时保留 Custom Renderer。                       |
| 事件数量爆炸           | 回溯、DP 和 O(n²) 算法产生大量事件。                                                 | 限制输入规模、支持宏/微步骤、合并重复事件和 checkpoint。                     |
| 设计系统失控           | 第三方 shadcn registry 组件风格不一致、维护困难。                                    | 固定基础风格和 tokens；第三方组件逐个审查后拷贝。                            |
| 动画与 React 状态耦合  | 中断、StrictMode 和重排导致错乱。                                                    | 播放器独立、算法状态纯函数化、动画可取消。                                   |
| 内容映射成本           | Markdown、代码片段与互动模块可能形成重复维护。                                       | MVP 采用显式 manifest 映射；稳定后再开发自动化适配器。                       |

# 12. 立项建议

> **建议决策**
>
> 批准一个以六个基准算法为范围的技术与产品 MVP。首要成果不是算法数量，而是形成可复用的事件协议、播放器、设计系统和四类核心 Renderer，并验证复合场景。MVP 评审通过后再批量接入《Hello 算法》内容。

1.  先完成冒泡排序技术原型：稳定实体 ID、Sequence Renderer、可取消播放和确定性回退。

2.  再完成 BFS、0-1 背包和 N 皇后，验证 Graph、Grid 和回溯。

3.  补充堆排序，验证 Composite Scene。

4.  完成统一算法页、代码面板、输入控制和移动端适配。

5.  通过性能、可访问性、视觉回归和内容授权评审后进入算法扩展阶段。
