# ADR 0001: 纯语义事件与不可变状态快照架构

## 状态
已接受 (Accepted)

## 上下文 (Context)
在传统算法可视化系统中，常见的实现方案有两类缺陷：
1. 使用 Proxy/状态拦截器隐式捕获数据读写，导致“比较”、“指针收缩”、“回溯”等教学意图难以精准表达；
2. 将算法逻辑状态与前端动画过渡（如 `onComplete` 回调、动画倒放）深度耦合，导致用户在拖拽时间轴（Seek）、反向单步回退或快速切页时频繁出现状态错乱和 DOM 闪烁。

## 决策 (Decision)
1. **显式语义打点**：算法函数作为纯计算逻辑，在执行过程中通过 `tracer.emit()` 和 `tracer.mark()` 显式输出与 UI、像素、动画时长解耦的纯语义事件。
2. **时间轴编译**：由统一的 `Timeline Compiler` 将事件流编译为带有视觉节奏、延迟偏移（cue offsets）和动效配方（Motion Recipe）的时间轴。
3. **不可变状态快照（State Snapshots）**：在生成 Trace 时，为每个 Marker 计算并保存一份不可变状态快照。前端 Seek、回退和前进直接以 $O(1)$ 速度读取快照状态，逻辑状态计算绝不依赖动画反向播放。
4. **防死循环熔断（Step Guard）**：Trace 生成器内置最大步数保护（如 10,000 步），防止用户异常输入导致主线程阻塞。

## 影响 (Consequences)
- **正面影响**：
  - 教学语义表达精确，算法可测试性极高（纯单元测试即可验证 Trace 与 Snapshot）。
  - 回退与进度条拖拽零延迟、零状态漂移，体验极其稳定。
  - 视觉动效与业务逻辑彻底解耦，UI/动效调整无需修改算法代码。
- **负面影响/权衡**：
  - 编写新算法时需要算法作者手动调用打点 API（相比黑盒拦截略多几行代码）。
  - 极长步骤算法会占用一定内存快照空间（已通过 Step Guard 规模限制与可选的 Checkpoint 抽样策略做缓冲）。
