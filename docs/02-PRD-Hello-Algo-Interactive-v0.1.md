> **产品定义**
>
> 用户在一个算法页面内完成“阅读解释 → 观察动画 → 对照代码与变量 → 修改输入 → 回放关键步骤”的闭环。不同算法可以使用不同视觉场景，但播放控制、交互语义和设计语言保持一致。

# 1. 产品概览

## 1.1 产品定位

面向算法学习者的交互式教材与可视化平台。它不是单纯的动画集合，也不是在线 IDE，而是把《Hello 算法》的知识内容与现代交互演示结合起来。

## 1.2 核心价值

- 看得懂：用连续运动和明确状态表达算法因果，而不是只展示前后快照。

- 跟得上：动画、代码、变量、解释和辅助数据结构同步。

- 能探索：支持步进、回退、拖动、变速、修改输入和可复现分享。

- 足够美观：统一的 UI、语义色彩、排版和运动语言。

- 可持续扩展：同一播放器支持多 Renderer 和复合场景。

## 1.3 产品目标与非目标

| **类型** | **内容**                                                                                 |
|----------|------------------------------------------------------------------------------------------|
| 目标     | 完成六个基准算法；建立可复用算法页、播放器、代码/变量面板、输入控制和四类核心 Renderer。 |
| 目标     | 形成统一的视觉与动画规范，确保不同算法看起来属于同一产品。                               |
| 目标     | 支持桌面与移动端核心流程，提供键盘操作和 Reduced Motion。                                |
| 非目标   | MVP 不提供账号、付费、在线判题、课程进度、社区和任意代码自动可视化。                     |
| 非目标   | MVP 不覆盖全部算法，也不要求所有语言代码真实执行。                                       |

| 复习者      | 快速回顾算法流程、复杂度和边界情况。         | 能通过自定义输入验证理解。               |

# 3. 核心用户流程

## 3.1 学习流程

```text
进入算法目录

→ 搜索或选择算法

→ 阅读概念与复杂度

→ 播放默认示例

→ 暂停 / 步进 / 回退

→ 对照代码与变量

→ 修改输入并重新运行

→ 分享当前输入或回到目录
```

## 3.2 首次访问流程

1.  用户进入算法页后看到已准备好的初始状态，默认不立即高速自动播放。

2.  主播放按钮和下一步操作位于稳定、易发现的位置。

3.  第一次点击播放后，代码、变量和场景同步推进。

4.  在关键 Marker 显示简短说明，用户可随时展开完整解释。

## 3.3 自定义输入流程

5.  用户打开输入配置。

6.  系统根据算法 schema 展示数组、目标值、图、矩阵或棋盘参数。

7.  输入即时校验；不合法时给出可修复提示。

8.  点击运行后生成新的确定性 trace，并重置到第一个 Marker。

9.  URL 可选择记录算法、输入和 seed，用于分享与复现。

## 4.2 桌面端算法页

```text
┌──────────────── 顶部导航 / 算法标题 / 全局操作 ────────────────┐

├──── 算法目录 ────┬──────── 主动画场景 ────────┬──── 代码 / 变量 ────┤

│ 分类 / 搜索 │ 复合场景、说明与输入 │ Tabs、当前行、状态 │

│ │ │ │

├──────────────────┴──────── 播放器与时间轴 ────┴────────────────────┤

└──────────────────────────────────────────────────────────────────┘
```

目录和右侧面板支持调整宽度与折叠。主动画区域始终拥有最高视觉优先级。

## 4.3 移动端算法页

- 主动画全宽显示，播放器固定在底部安全区域。

- 目录、代码、变量和输入通过 Sheet/Drawer 打开。

- 复合辅助场景使用 Tabs 或可折叠卡片，不强行并排。

- 不提供依赖 hover 的唯一交互。

# 6. Renderer 产品要求

## 6.1 Sequence Renderer

- 适用于数组、字符串、排序、二分、双指针和滑动窗口。

- 元素具有稳定 ID；重复值仍被视为不同实体。

- 支持 value cell、bar、token 三种展示变体，但共享语义状态。

- 比较、选择、换位、写入、指针、区间和完成状态必须有统一视觉 recipe。

## 6.2 Linked Renderer

- 适用于链表、栈、队列、哈希桶和 LRU。

- 节点使用 DOM，连接关系使用 SVG 覆盖层；节点与边均有稳定 ID。

- 删除动作需表现为断开 → 退出 → 重连，而非瞬间消失。

## 6.3 Graph / Tree Renderer

- 使用 React Flow 处理节点、边和视口；算法演示模式默认禁止编辑与随意拖动。

- 算法执行期间位置尽量固定；只有结构变化时重新布局。

- 支持节点访问、边检查、路径、距离更新、插入、旋转和子树移动。

- 复杂阴影、持续发光和大量并行动画需要受控，避免影响大图性能。[R5]

## 6.4 Grid / Board Renderer

- 中小规模使用 CSS Grid；性能数据表明需要时再启用 Canvas Renderer。

- 支持依赖单元格、当前单元格、写入、候选、冲突、路径和已完成状态。

- DP 动画应先强调依赖，再写目标值，突出计算因果。

## 6.5 Composite Scene

一个算法可以声明多个 Scene。产品层根据屏幕尺寸决定并排、上下或 Tabs 展示，但所有 Scene 由同一个 Transaction 和 Marker 驱动。

| **算法** | **主场景**      | **辅助场景**                   |
|----------|-----------------|--------------------------------|
| BFS      | Graph           | Queue、Visited 集合            |
| Dijkstra | Graph           | Priority Queue、Distance Table |
| 堆排序   | Array           | Heap Tree                      |
| 0-1 背包 | DP Grid         | Items 与容量信息               |
| N 皇后   | Board           | Call Stack / 候选列            |
| 归并排序 | Source Sequence | Temporary Sequence             |

# 7. 动画体验规范

## 7.1 视觉语义

| **语义**  | **视觉表现**                                 | **禁止做法**                             |
|-----------|----------------------------------------------|------------------------------------------|
| 比较      | 两个目标轻微抬起、边框增强，其他对象降权。   | 整屏闪烁或持续跳动。                     |
| 交换/移动 | 实体沿可理解路径移动，结束后稳定落位。       | 直接互换高度、文本或颜色而无空间连续性。 |
| 访问      | 节点或单元格短暂 pulse，边按方向绘制。       | 无限循环发光。                           |
| 写入      | 旧值淡出或收缩，新值进入，依赖先于结果出现。 | 数值无提示瞬间变化。                     |
| 冲突      | 短暂危险色、冲突关系或线路出现。             | 高频抖动和强烈震动。                     |
| 回溯      | 路径反向收缩，已尝试实体退出。               | 直接切回旧快照。                         |
| 完成      | 状态统一收敛，给出一次轻量确认。             | 大量彩带或遮挡内容的庆祝效果。           |

## 7.2 运动原则

- 算法动作使用统一 Motion Tokens；单个算法不得随意发明时长、颜色和弹簧参数。

- 比较通常短于移动；结构变化通常长于纯状态变化。

- UI 微动画和算法动画共享风格，但不得抢夺主场景注意力。

- 动画中断后必须能落到明确状态；不得依赖 onComplete 才提交算法结果。

- Motion 支持 layout、序列控制和 Reduced Motion，可作为统一 React 动画运行时。[R4]

# 8. 产品状态与异常处理

| **状态**      | **表现**                              | **用户可执行操作**           |
|---------------|---------------------------------------|------------------------------|
| 初始          | 显示默认输入、第一 Marker、概念摘要。 | 播放、下一步、修改输入。     |
| 生成中        | 输入控件锁定，展示轻量加载。          | 取消或返回默认示例。         |
| 播放中        | 主控件显示暂停；允许调速。            | 暂停、调速、拖动或切换算法。 |
| 暂停          | 保持当前中间态或 settled Marker。     | 继续、前后步进、拖动。       |
| 结束          | 显示结果、复杂度和重播入口。          | 重播、修改输入、分享。       |
| 输入错误      | 字段级错误与整体说明。                | 修正输入或恢复默认。         |
| 事件过多      | 说明规模过大并给出推荐范围。          | 缩小输入、启用快速模式。     |
| Renderer 异常 | 保留文本步骤和代码，显示错误边界。    | 重试、恢复默认、反馈问题。   |

# 9. 非功能需求

| **类别** | **要求**                                                                            |
|----------|-------------------------------------------------------------------------------------|
| 一致性   | 相同输入、seed 和 schemaVersion 必须产生一致事件；前后重放状态相同。                |
| 性能     | 六个基准算法在常见现代设备上保持流畅；不通过全局 React 状态逐帧驱动。               |
| 可访问性 | 键盘完整操作、Reduced Motion、文字步骤、焦点可见、颜色非唯一信号。                  |
| 响应式   | 桌面、平板和移动端都有专门布局；核心操作不依赖 hover。                              |
| 稳定性   | 快速连续操作、Resize、切换算法和路由离开均可取消当前动画。                          |
| 可观测性 | 记录算法加载、trace 生成错误、Renderer 错误和性能基准，不记录敏感输入。             |
| 浏览器   | MVP 面向 Tailwind v4 与 Vite 所支持的现代浏览器；如需旧浏览器另行评估。[R7][R8] |

# 10. MVP 范围

| **算法** | **默认输入示例**     | **核心验收**                                    |
|----------|----------------------|-------------------------------------------------|
| 冒泡排序 | \[4, 1, 3, 1, 5, 2\] | 重复值稳定 ID；比较与换位自然；可前后步进。     |
| 二分查找 | 有序数组 + target    | left/mid/right 与排除区间清晰；未找到状态正确。 |
| BFS      | 小型无向图 + 起点    | 节点、边、队列和访问顺序同步。                  |
| 堆排序   | 7~10 个整数          | 数组与树的同一实体对应；交换同步。              |
| 0-1 背包 | 少量物品 + 容量      | 依赖单元格、选择关系和写入顺序清楚。            |
| N 皇后   | n=4 或 n=5           | 尝试、冲突、撤销和调用栈完整可见。              |

# 11. MVP 明确不包含

- 账号、云同步、收藏和学习进度。

- 用户提交任意代码并自动分析。

- 在线编译、沙箱运行和判题。

- 多人协作课堂、评论和讨论区。

- 全部语言代码的实时行映射。

- 大规模图或超大矩阵的高性能 Canvas/WebGL 支持。

# 12. 数据与指标

MVP 以质量验证为主，建议记录下列匿名产品事件，具体埋点方案可在开发阶段确定：

- algorithm_open：打开算法。

- playback_start / pause / complete：播放生命周期。

- step_forward / step_back / seek：主动探索行为。

- input_run / input_error：自定义输入使用情况。

- code_language_change：代码语言切换。

- renderer_error / trace_limit：稳定性与规模问题。

> **隐私原则**
>
> 默认不上传完整用户输入、算法事件序列或可识别信息。若未来接入分析平台，应允许关闭非必要分析。

> ☐ 快速连续操作不会产生重叠播放、双重计时或状态错乱。
>
> ☐ 重复值、重复标签和相同棋子不会因 React key 错误而重建。
>
> ☐ 代码锚点、变量、描述和所有 Scene 在同一个 Marker 对齐。
>
> ☐ 移动端可完成完整学习流程，代码和目录通过 Drawer/Sheet 访问。
>
> ☐ Reduced Motion 开启后仍能理解所有状态变化。
>
> ☐ 每个算法有 reducer/replay 测试；关键 Marker 有视觉回归截图。
>
> ☐ 内容来源、修改说明和授权信息在产品中可访问。
